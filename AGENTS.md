# Agent rules
- Balance-link checkout requests are memoized per mounted page and token so React effect replays cannot create competing pending payments.
- Article social images use the public read-only `/api/public/og` endpoint; shared URL generation keeps route metadata and BlogPosting schema identical, and edge-safe resvg renders bundled fonts/logo using global `--og-*` tokens without runtime filesystem access. Static previews remain explicitly assigned to their existing routes.
- Matching rules live in `src/lib/matching.ts` (pure, tested) and run server-side via `src/lib/matching.server.ts`; match emails/Slack go through `src/lib/match-slack.server.ts` — one code path for manual, auto and HR API changes.
- The HR automation API is a TanStack server route (`/api/public/hr-api/*`), not an edge function; it checks `x-hr-api-key` and writes every call to `hr_api_audit`, which also backs its rate limit.
- Every `CREATE TABLE` in `public` must carry explicit GRANTs (authenticated + service_role, anon only for public reads) in the same migration; Supabase stopped auto-granting Data API access on 2026-10-30, so a table without GRANTs returns "permission denied" through the Data API.
- WhatsApp Business messaging goes through `src/lib/whatsapp.server.ts` (gateway send + records outbound); Meta callbacks hit `/api/public/whatsapp/webhook`, are stored in `whatsapp_webhook_events` before processing, and failed rows retry with backoff on later calls.
- Promotional lead-email sequences are disabled by default and excluded from the app-email registry; future dispatch requires explicit email consent and a dedicated marketing provider to protect app-email delivery.
- Lead forms use column-only INSERT grants: grant new visitor-submitted fields to anon/authenticated in the same migration, while keeping consent timestamps, versions and staff fields server-controlled.
- Class dates are per student: read them from the `student_timetable(faculty_id)` database function, never from `lectures.scheduled_at`, because each student starts class 1 from their own start date.
- Lead WhatsApp campaigns: segment rules live in `src/lib/whatsapp-campaign.ts` (pure, tested); sends go through `sendWhatsApp` with a reserve-then-send row in `whatsapp_campaign_sends` (unique per campaign+lead, one per phone) so repeated clicks never double-message, and STOP opt-outs are always skipped.
- Slack community assistant lives in `src/lib/slack-community.ts` (pure, tested) + `.server.ts`; Slack events hit `/api/public/slack/events` (signature-verified, answered after ack via `runAfterResponse` in `src/lib/worker-ctx.ts`), one answer per thread logged in `slack_assistant_log`.
- Class video links follow one rule in `supabase/functions/_shared/class-videos.ts` (pure, tested): only real curated `class_videos` rows (our Drive videos + checked YouTube videos, managed at /admin/class-videos) are shown as videos, AI-suggested YouTube links are dropped; the dashboard handout (generate-class-content) and the Slack "next class" post (`briefNextClass`) both use it.
- Drive class videos stay "Restricted". `openClassVideos` (src/lib/student-review.functions.ts) adds a student's email as Viewer on the Drive videos of classes 1..current (current class read from `course_progress` server-side) via the Apps Script in `scripts/drive-share/` (secrets DRIVE_SHARE_URL, DRIVE_SHARE_SECRET). Never share a folder or "anyone with the link".
- One pending WhatsApp/email/bank request per student and plan: a trigger on `enrollments` skips a repeat request and cancels the other pending rows for a plan once one is paid; Admin > Payments to confirm groups any remaining copies (`src/lib/pending-requests.ts`) and settles them together.
- The free Bootcamp Starter programme is "Everyday AI & Digital Productivity": its `bootcamp_starter` courses and class titles are AI topics, not web dev (migration 20261107160000).
